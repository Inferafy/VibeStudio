# 外部工具层：Agent 接入

模块定位：记录现成 Claude、Codex 适配器与原编程工具的接入方式和实测能力。

所属分层：[外部工具层](../架构设计.md#1-总体与分层)。

对应代码：上游适配器与原 CLI；本项目无自制桥接程序，计划由 `src-tauri/src/acp/` 调用。

所属里程碑：[M0](../roadmap.md#m0)、[M2](../roadmap.md#m2)、[M3](../roadmap.md#m3)。

当前状态：未开始。

最近更新时间：2026-09-14。

## 职责与边界

- M0 记录目标版本、运行环境、启动方式、原工具认证、新建及原会话续聊结果。
- 记录权限、模型、思考等级和上下文用量的支持情况，区分已验证、上游不支持与尚未验证。
- M2 核对真实聊天、工具记录、提问、审批和停止；M3 验证混合并行及可运行包的依赖条件。
- 编程执行和原生历史由上游负责；不采用 VibeX 完整工程，不重写桥接或统一认证系统。

## 结构与数据流

本地运行模块连接现成适配器，适配器调用原编程工具；事件通过 ACP 返回，原生历史仍保存在原工具中。

## 关键决策

沿用 [接入技术选择](../技术设计.md#1-技术选择)。具体版本与能力只在真实验证后确认；不兼容时记录并讨论处理方式，不用新上下文掩盖失败。

## 当前实现

此前已有接入方式调研，目标 Windows 环境下的双 Agent 续聊与完整能力尚未完成实测。本文件尚无已验证的版本兼容结论。

## 验证方式

使用专用项目和可辨识会话验证新建与历史续聊，留下版本、操作及结果依据；对支持的交互做真实联调，明确不支持的能力，不把原型演示值作为证据。

## 待扩展项

M0 前确认最小验证设计，随后补齐版本和能力记录、失败边界及 M2、M3 联调结果。更多 Agent 和自动安装分发方案后续再讨论。
