# 外部工具层：Agent 接入

模块定位：记录现成 Claude、Codex 适配器与原编程工具的接入方式和实测能力。

所属分层：[外部工具层](../架构设计.md#1-总体与分层)。

对应代码：M0 临时探针保留为本机忽略资产，可审计源码见历史提交 [`4d884db`](https://github.com/Inferafy/VibeStudio/commit/4d884db)；生产实现计划由 `src-tauri/src/acp/` 调用。

所属里程碑：[M0](../roadmap.md#m0)、[M2](../roadmap.md#m2)、[M3](../roadmap.md#m3)。

当前状态：进行中。

最近更新时间：2026-09-14。

## M0 目标与退出边界

M0 只回答一个前置问题：在当前 Windows 环境下，Claude Code 和 Codex 是否能通过各自的现成适配器完成新建会话、加载原会话并继续原上下文。

M0 通过后，才允许进入工作台和聊天实现。M0 不代表完整聊天能力已经完成，也不提前承诺两个 Agent 的权限、模型、思考等级和上下文用量都可用；这些能力必须逐项记录真实结果。

以下情况都不能算通过：

- 只显示旧标题，实际启动了空白会话。
- 续聊后的回复无法证明来自原会话上下文。
- 适配器、版本、启动命令或认证来源没有留下可复核记录。
- 失败时悄悄换成新会话，或修改、迁移、删除原始会话记录。

## 职责与边界

- M0 记录目标版本、运行环境、启动方式、原工具认证、新建及原会话续聊结果。
- 记录权限、模型、思考等级和上下文用量的支持情况，区分已验证、上游不支持与尚未验证。
- M2 核对真实聊天、工具记录、提问、审批和停止；M3 验证混合并行及可运行包的依赖条件。
- 编程执行和原生历史由上游负责；不采用 VibeX 完整工程，不重写桥接或统一认证系统。

M0 的验证对象固定为两类来源：Claude Code、Codex。VibeX 只作为 ACP 接入方式的参考实现，不作为 VibeStudio 的运行时依赖或代码底座。

## M0 固定记录

M0 已锁定 Codex 适配器 `1.11.0`、Claude 适配器 `0.77.0` 和 Rust ACP SDK `2.1.0`。后续升级前仍须重新记录以下信息，不能用仓库链接或原型中的模型名称代替。

| 记录项 | 内容要求 |
| --- | --- |
| 运行环境 | Windows 版本、Node、pnpm、Rust 及目标 Agent 版本 |
| 适配器 | 包名、版本或提交、来源地址、与 Agent 的对应关系，以及适配器实际携带或调用的 Agent/SDK 版本 |
| 启动方式 | 可执行文件或命令、参数、工作目录、是否经过 Node 包管理器 |
| 认证来源 | 沿用原工具的配置或环境变量名称；绝不记录密钥、令牌和 Cookie |
| 会话标识 | 原生会话 ID、来源 Agent、工作目录及新建/恢复关系 |
| 运行结果 | 每个验证步骤的开始时间、结束状态、可观察事件和失败原因 |

Windows 启动契约只保存真实使用过的可执行文件、参数和工作目录。除非适配器明确要求，不通过字符串拼接或额外 shell 包装改变参数边界。

## 结构与数据流

本地运行模块连接现成适配器，适配器调用原编程工具；事件通过 ACP 返回，原生历史仍保存在原工具中。M0 的最小数据流如下：

1. 读取已配置的 Agent、适配器和专用测试项目，不读取或改写其他项目的会话。
2. 启动适配器并完成握手，记录实际命令、进程和连接结果。
3. 新建会话，保存适配器返回的原生会话标识，并发送带唯一记忆点的测试内容。
4. 结束本次验证所拥有的进程，再用同一 Agent、工作目录和原生会话标识发起恢复。
5. 检查历史、回复内容、工作目录和可观察能力，形成一条可复核的验证记录。

恢复时不重新生成会话标识，不从标题或最近活动时间推断上下文归属。

## 关键决策

沿用 [接入技术选择](../技术设计.md#1-技术选择)。M0 采用最小、短生命周期的验证进程，避免把进程复用、后台驻留和完整客户端状态混入接入结论。

具体版本、启动参数和能力只在真实验证后确认。适配器不兼容时，记录失败边界并进入决策，不用新上下文掩盖失败。

跨 Agent 的上下文转换不属于 M0。一个原生会话只能绑定它所属的 Agent；切换 Agent 必须创建或明确选择另一条会话。

## M0 能力矩阵

每一项使用四种结果之一：`已验证`、`上游不支持`、`验证失败`、`未验证`。只有写明证据位置后，才允许使用前三种结果。

| 能力 | M0 检查内容 | 正式接入阶段 |
| --- | --- | --- |
| 新建会话 | 两类 Agent 都能创建并返回原生会话标识 | M2 |
| 加载旧会话 | 使用原生会话标识加载历史，不新建空白上下文 | M2 |
| 真实续聊 | 能根据唯一记忆点给出可辨识回复 | M2 |
| 历史消息 | 能观察到足以证明上下文连续的历史或事件 | M2 |
| 权限 | 能否读取当前权限、发出审批请求和表达限制 | M2 |
| 模型 | 能否读取或设置当前模型；不支持时记录原因 | M2 |
| 思考等级 | 能否读取或设置思考等级；不支持时记录原因 | M2 |
| 上下文用量 | 能否得到可靠的使用量或明确不可用 | M2 |
| 工具记录、停止、错误 | 只记录适配器是否暴露相关能力，不在 M0 完成完整交互 | M2 |
| 原生命令 | 是否动态上报名称、说明和参数提示，恢复会话后是否仍正确 | M2 |
| 工具生命周期 | 是否上报调用标识、类型、状态、结果、文件位置或终端 | M2 |
| 客户端能力 | 终端、文件、表单提问等反向请求分别支持到什么程度 | M2 |

原型里的模型、权限、思考等级和上下文百分比只能作为界面对照，不能填入能力矩阵。

## 原生命令与工具接入

[Agent 原生命令与工具接入调研](../调研/Agent原生命令与工具接入调研.md) 已确认 ACP 的基本链路及两类适配器的当前做法。外部工具层只记录适配器实际暴露的原始能力和版本边界，内部归一化与状态管理交给 [Agent 原生能力](本地能力层-Agent原生能力.md)：

- 命令列表来自当前会话的 `available_commands_update`，客户端不维护跨 Agent 的静态全集。
- 用户选中的 `/命令` 作为普通会话内容发送，适配器负责把需要的命令转换为原生 SDK、App Server 或 CLI 行为。
- 工具调用、审批、终端、配置和取消使用各自的协议事件或方法，不能用命令文字代替。
- Claude 适配器会过滤依赖原生终端的命令；Codex 适配器会把一部分命令翻译成 App Server 调用。VibeStudio 只展示适配器实际声明的集合。
- 适配器及其内部 Agent 运行依赖必须成对锁定和记录；上游最新版本只能作为候选，不能直接视为兼容。

## 当前实现

M0 使用独立 Rust ACP 探针锁定两类适配器及依赖，完成初始化、新建、加载、恢复、配置修改、审批拒绝、取消、事件归属和脱敏结果记录。探针已退出正式产品代码，源码保留在历史提交，本机副本继续供兼容性复核。

[M0 双 Agent 接入验证](../验证记录/M0/2026-09-14-双Agent接入验证.md) 已确认当前 Windows 环境下两类 Agent 的 ACP 会话和原生 CLI 会话都能真实续聊。M2、M3 的完整聊天和并行联调仍待后续实现。

## 验证方式

使用专用项目和可辨识会话验证新建与历史续聊，留下版本、操作及结果依据；对支持的交互做真实联调，明确不支持的能力，不把原型演示值作为证据。

每个 Agent 至少完成以下验证序列：

1. 记录版本、适配器、启动方式和认证前提。
2. 创建专用项目和新会话，发送唯一记忆点并确认回复。
3. 关闭验证进程，重新使用原生会话标识加载历史。
4. 发送只依赖此前记忆点的问题，确认回复来自原上下文。
5. 记录权限、模型、思考等级、上下文用量、原生命令和客户端反向请求的实际结果。
6. 执行一个只读命令并观察一次工具生命周期，确认事件始终归属原会话。

验证摘要归档到 `docs/验证记录/M0/`，原始输出保存在本机临时位置。提交到仓库的记录必须去除密钥、令牌、Cookie 和无关用户路径。
