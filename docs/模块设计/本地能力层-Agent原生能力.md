# 本地能力层：Agent 原生能力

模块定位：把不同 ACP Agent 上报的命令、配置、工具、审批和客户端请求整理为按会话隔离的统一业务能力。

所属分层：[本地能力层](../架构设计.md#1-总体与分层)。

对应代码：[M0 ACP 探针](../../tools/m0-acp-probe/)；生产实现计划使用 `src-tauri/src/acp/capabilities/`、`src-tauri/src/acp/events/` 和 `src-tauri/src/acp/client_capabilities/`。

所属里程碑：[M0](../roadmap.md#m0)、[M2](../roadmap.md#m2)。

当前状态：进行中。

最近更新时间：2026-09-14。

## 职责与边界

- M0 记录协议版本、初始化能力、原生命令、配置选项、提示词类型、工具事件及客户端反向请求的真实支持范围。
- M2 将适配器事件归一为界面可消费的会话能力、工具状态、审批、提问、用量和通知。
- 保存每个会话的完整能力快照，处理运行中的完整更新和适配器扩展。
- 校验命令、配置、权限和工具事件归属，拒绝未知会话或已失效请求。
- 不负责适配器安装、版本选择、认证、进程启动、会话恢复、连接生命周期或界面展示。

[Agent 接入](外部工具层-Agent接入.md) 负责外部适配器与原工具，[会话运行](本地能力层-会话运行.md) 负责连接和执行生命周期，本模块只处理连接上流动的能力与业务事件。

## 结构与数据流

```text
ACP 初始化、会话建立和 session/update
  -> 能力与事件归一化
       -> 会话能力快照
       -> 命令与配置更新
       -> 工具调用状态
       -> 审批与提问请求
       -> 用量、通知和未知扩展
  -> 会话运行模块按目标会话发布
  -> 界面层读取与操作
```

界面返回的命令、配置修改、审批、提问和取消先经过本模块校验，再交给会话运行模块发送到原连接。

## 核心对象

| 对象 | 内容 | 更新规则 |
| --- | --- | --- |
| 会话能力 | 协议、提示词、终端、文件、提问、权限和扩展能力 | 会话建立时创建，能力协商后更新 |
| 可用命令 | 名称、说明、参数提示和来源 | 收到完整命令更新时整体替换 |
| 会话配置 | 标识、名称、分类、当前值和可选值 | 收到完整配置更新时整体替换 |
| 工具调用 | 调用标识、类型、标题、状态、内容、位置和终端 | 按调用标识合并增量更新 |
| 交互请求 | 请求标识、会话、类型、选项、有效状态 | 回答、取消、回合结束或断线后失效 |
| 用量与通知 | 上下文、成本、警告、压缩和错误 | 只保存 Agent 可确认的数据与来源 |

原始协议数据保留在验证或诊断边界，界面读取经过归一化的业务对象。未知字段和扩展不会静默丢失。

## 原生命令

- 命令列表只接受当前会话的动态上报，不能按 Agent 名称硬编码全集。
- 用户选择的 `/命令 参数` 作为普通会话内容发送，由 Agent 或适配器解释。
- `$技能` 与 `/命令` 保留不同来源；没有上报的技能不扫描或猜测。
- 停止、配置修改和审批使用专门协议方法，不降级为命令文字。
- 本地可以给已知命令补图标和中文名称，但发送值必须保持原样。

## 工具与客户端能力

- 工具状态按调用标识合并；完成、失败或取消后，迟到事件不能把状态改回运行中。
- 审批按钮采用 Agent 返回的选项。答复一次后请求立即失效，回合取消时所有待处理请求同步取消。
- 终端、文件读写、表单提问等客户端能力分别声明和验证；只声明已经实现的部分。
- 无法识别的工具和扩展转为通用事件并保留类型、状态和诊断摘要。
- 适配器特有扩展必须先完成双向能力协商和真实验证，再进入稳定业务接口。

详细协议和开源实现依据见 [Agent 原生命令与工具接入调研](../调研/Agent原生命令与工具接入调研.md)。

## 关键决策

- 能力以会话为边界，不能把一个 Claude Code 会话的命令或配置复制给 Codex 会话。
- 完整更新覆盖旧快照，增量工具事件按稳定调用标识合并；两类更新不能混用。
- 业务层保留“上游不支持、尚未验证、验证失败、已验证”四种事实，缺失能力不生成假默认值。
- Codex App Server 和 Claude Agent SDK 由对应适配器封装，VibeStudio 的稳定入口继续使用 ACP。
- M0 探针先记录原始初始化、会话建立和事件数据，正式归一化接口在 M2 开工前依据实测结果冻结。

## 当前实现

已完成 ACP、VibeX、CodeG 及 Claude/Codex 适配器调研，并通过 [M0 双 Agent 接入验证](../验证记录/M0/2026-09-14-双Agent接入验证.md) 取得两类 Agent 的真实命令、配置、工具、审批、用量和取消事件。探针已实现原始事件收集、历史回放分离、命令快照去重和审批记录；正式能力归一化代码、持久状态和界面接口尚未实现。

## 验证方式

- 为完整命令/配置替换、工具状态合并、未知事件保留、请求失效和跨会话隔离编写单测。
- M0 分别验证两类 Agent 在新建、加载和恢复会话后上报的命令、配置和客户端能力。
- 每类 Agent 至少执行一个只读命令，观察一次工具生命周期，并完成一次权限或提问往返。
- 核对取消、断线和回合结束后待处理请求与未完成工具状态正确收束。
- 版本升级后重新运行能力验证，旧版本记录只能作为对照。
