# 本地能力层：会话扫描

模块定位：只读整理 Claude Code、Codex 原生会话，并按真实项目目录组织。

所属分层：[本地能力层](../架构设计.md#1-总体与分层)。

对应代码：[扫描模块](../../src-tauri/src/scanner/)、[前端目录类型](../../src/sessions/types.ts)。

所属里程碑：[M1](../roadmap.md#m1)。

当前状态：进行中。

最近更新时间：2026-09-15。

## 职责与边界

- 只读扫描 Claude Code JSONL 与 Codex SQLite，提供来源、原生会话标识、标题、工作目录、记录位置和最近活动时间。
- 分别报告两类来源的可用、部分可用或不可用状态；单条损坏记录和单个来源失败不能清空其他有效结果。
- 按真实工作目录合并项目，保留原始展示路径和独立归属键，不用标题或最近活动时间推断会话归属。
- 不启动 Agent，不迁移、改写或删除原始记录，也不把“目录存在”表达成“会话一定可以续聊”。

## 结构与数据流

```text
src-tauri/src/scanner/
  mod.rs                  对外导出目录结果
  types.rs                会话、项目、来源状态等传输对象
  catalog.rs              调度来源扫描、分组、排序和警告合并
  providers/
    mod.rs                统一来源扫描结果
    claude.rs             Claude Code JSONL 只读解析
    codex.rs              Codex SQLite 只读解析
```

扫描顺序如下：

1. 配置模块给出用户覆盖路径；没有覆盖时按原工具默认位置解析。
2. 两个来源在阻塞任务线程中分别扫描，任何一方失败都形成来源状态和警告。
3. 有效会话按“来源 + 原生会话标识”去重，再按规范化工作目录分组。
4. 项目按最近活动排序，会话在项目内按最近活动倒序排列。
5. Tauri 命令一次返回目录快照；前端不直接接触 JSONL、SQLite 或用户目录。

## 结果约定

| 对象     | 必要内容                                               | 说明                                                         |
| -------- | ------------------------------------------------------ | ------------------------------------------------------------ |
| 会话摘要 | 来源、原生标识、标题、工作目录、记录位置、最近活动时间 | 标题为空时使用明确回退值；记录位置仅供诊断和后续只读历史入口 |
| 项目摘要 | 稳定归属键、展示名称、展示路径、会话集合、最近活动时间 | 展示路径保留原始大小写，归属键单独计算                       |
| 来源报告 | 来源、可用状态、有效数量、警告                         | 不把来源失败伪装成空目录                                     |
| 目录快照 | 项目集合、来源报告、扫描时间                           | 每次扫描生成完整快照，界面决定是否保留上次成功结果           |

Rust 字段统一以 `camelCase` 传给 TypeScript；时间使用 Unix 毫秒。前端使用运行时结构校验，并与 Rust 单测读取同一份完整 JSON 样本，字段变化必须同时通过两端测试。

## 复用范围

以 CCSM 固定提交 [`af216a9`](https://github.com/evepupil/CCSM/commit/af216a912b6998e6650407376e397b7c7bd42617) 为主参考，直接迁移以下已运行行为：

- Claude Code 的逐行容错、用户自定义标题优先级和会话元数据提取。
- Codex 状态库只读连接、字段兼容和标题回退。
- 两类来源独立失败、统一警告、项目分组和排序。
- 前端十秒自动刷新及防止上一次扫描未结束时重复发起。

不迁移 CCSM 的 CLI 启动、终端识别、工作区恢复、消息预览、HeroUI 页面和样式。以下问题在移植时修正：扫描放入阻塞线程；Claude Desktop 标题增强改成可注入来源；最高编号 Codex 状态库损坏时尝试旧库并返回警告；`canResume` 改为只表达工作目录是否可用。

## 关键决策

- 扫描器输入路径必须可注入，单测只读临时样本，不能读取真实用户目录。
- Windows 路径先去除长路径前缀并尽量规范化；规范化失败时保留原路径并产生警告，不能丢弃整条会话。
- 自动刷新先沿用十秒间隔和防重入。数据量需要优化时再依据测量加入按修改时间缓存。
- 会话是否真正可续聊由 M0 已验证的 ACP 路径在 M2 加载时确认，扫描层只描述“发现了什么”。

## 当前实现

正式模块目录和跨前后端传输对象已经建立，覆盖来源、会话、项目和来源状态；同一份完整样本已经同时进入 Rust 序列化测试与 TypeScript 运行时校验测试。Claude、Codex 的实际扫描及目录聚合尚未移植，因此当前界面只显示空状态。

## 验证方式

- 使用临时 JSONL 验证损坏行容错、标题优先级、目录提取和重复标识处理。
- 使用临时 SQLite 验证只读打开、字段兼容、数据库回退和损坏库警告。
- 使用混合样本验证一个来源失败时另一来源仍返回、项目分组和排序稳定。
- 使用固定 JSON 契约样本核对 Rust 输出字段与 TypeScript 类型；对真实目录只做只读抽样，不修改原始记录。
