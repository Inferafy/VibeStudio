# VibeStudio 技术设计

依据 [需求设计](需求设计.md)，本文记录已确认的技术选择和粗目录划分。MVP 只实现会话扫描、ACP 统一聊天，以及单会话和网格会话。

完整界面布局与后续功能入口继续保留，项目视图、画布及其他开发工具后续补齐。架构分层和模块内部细节在对应设计阶段讨论，不在这里提前展开。

## 1. 技术选择

| 方面 | 选择 |
| --- | --- |
| 桌面 | Tauri 2 + Rust 2024，方便复用 CCSM 的扫描代码 |
| 前端 | React 19 + TypeScript 严格模式 + Vite 8 |
| 控件与样式 | shadcn/ui + Tailwind CSS + Lucide，统一主题和基础控件，参考 Codex 风格 |
| 会话扫描 | 复用 CCSM 的 Claude 会话解析、Codex 只读索引和项目分组 |
| Agent 接入 | Rust 使用现成 ACP 协议库，连接现成 Claude、Codex 适配器，不自写完整桥接程序 |
| 本地保存 | JSON 保存必要配置和会话关联；历史由原工具保存，不新建业务数据库 |

### 前端基础

保留需求文档中的项目栏、一级视图切换、会话工作区和画布位置。

开发业务界面前先建立统一主题和基础控件，各区域复用同一套样式与交互。MVP 只实现会话业务，不提前建设编辑器、Git 面板或画布业务。

### 会话扫描与接入

扫描保持只读，复用 CCSM 已有的解析与项目分组能力，不改写、迁移或删除原始会话。

统一聊天使用现成 ACP 协议库和两类适配器。原编程工具负责实际开发执行，本客户端负责会话选择、消息展示、必要审批及停止操作。

原生命令、模型、模式、思考等级和权限选项以当前会话的适配器上报为准，前端不按 Agent 名称写死能力表。用户选择的 ACP 原生命令作为会话内容发送，由适配器解释；工具调用、审批、配置和取消使用对应协议事件或方法。

Codex 适配器可以在内部使用 Codex App Server，Claude 适配器可以在内部使用 Claude Agent SDK；VibeStudio 在 MVP 中仍只连接 ACP，不同时维护第二套直连接口。

Node 只用于运行上游适配器，不增加自制服务、后台平台或另一套 Agent 引擎。

### 本地数据

只保存必要接入配置及会话标识关联，不复制原工具的完整历史到新的业务数据库。

原工具继续保存自己的会话历史，客户端按需扫描和加载。

## 2. 目录划分

正式工程按已确认职责拆分：

```text
src/app/                 项目栏、导航和整体布局
src/sessions/list/       会话列表、搜索和来源筛选
src/sessions/conversation/ 会话内容、过程卡和待处理交互
src/sessions/composer/   输入、命令候选和会话控件
src/sessions/grid/       单会话面板与网格编排
src/shared/components/   shadcn 风格基础控件
src/shared/styles/       主题 Token 与全局样式
src/shared/lib/          公共纯函数
src-tauri/src/commands/  Tauri 本地命令入口
src-tauri/src/state.rs   配置与 ACP 运行实例的唯一应用状态
src-tauri/src/scanner/   会话扫描、来源解析和目录结果
src-tauri/src/acp/runtime/ 连接、会话恢复和执行生命周期
src-tauri/src/acp/capabilities/ 原生命令、配置和工具事件归一化
src-tauri/src/acp/client_capabilities/ 终端、文件和提问等客户端能力
src-tauri/src/settings/  本地配置与后续会话关联
```

按职责拆分组件与逻辑，避免把扫描、接入和界面状态集中在单个文件中。

## 3. 工程规范

- 使用 Windows 工具链：Node.js 24、pnpm 10、Rust stable；依赖精确结果由 `pnpm-lock.yaml` 和 `Cargo.lock` 固定。
- TypeScript 开启严格模式、未使用项检查、可选字段精确检查和索引访问检查。
- 生产 WebView 使用只允许本地资源和 Tauri IPC 的 CSP；开发环境只为 Vite 热更新放开 HTTP 与 WebSocket。
- 使用项目换行规则和统一格式化，避免平台切换制造无关文件差异。
- 提交前运行格式化、静态检查和核心业务单测。
- 扫描、会话关联、消息及审批路由等核心逻辑编写单测。
- 主题、配色、布局等纯界面外观通过实际操作检查，不编写外观单测。

统一门禁由 `pnpm gate` 执行，覆盖 Prettier、TypeScript、Vitest、Rustfmt、Clippy、Rust 单测、前端生产构建和 Tauri 无安装包构建。本阶段不额外引入大型测试平台。
