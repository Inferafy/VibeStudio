# 会话内容与操作调研

调研日期：2026-09-14。

关联模块：[界面层：会话内容与操作](../模块设计/界面层-会话内容与操作.md)、[界面层：聊天与网格](../模块设计/界面层-聊天与网格.md)。

当前状态：调研完成；按钮范围在 M2 开工前确认，真实显示效果随接入能力验证。

## 1. 目的与结论

本调研回答两个问题：成熟 Agent 客户端怎样展示一次会话中的不同内容，以及 VibeStudio 需要准备哪些操作入口。

结论如下：

- 会话正文应是一条统一时间线，用户消息、Agent 回复、思考、计划、工具、命令、文件变化、审批、提问和错误各有稳定展示方式。
- 文字直接阅读；思考、长工具输出和完整差异默认收起，让用户先看任务进展和最终回复。
- 操作紧贴对象：回复旁放复制，工具卡内放展开，审批卡内放决策，输入区只放发送、停止和当前会话能力。
- 单会话和网格复用同一份会话内容。网格缩短摘要并保留审批、提问和错误等必须处理的状态。
- 开源项目中的完整按钮很多，VibeStudio 只吸收与当前 MVP 直接相关的部分，任务管理、复杂分栏、终端和完整代码工作区继续后置。

本文把来源分为“源码事实”“官方资料”和“建议”。截图只能证明画面中可见的部分，不能代替代码行为或真实接入验证。

## 3. 开源项目怎样展示会话

### 3.1 CodeG

CodeG 的会话按用户、助手和系统角色组织，内容块覆盖文字、图片、生成图片、工具调用、工具结果、思考和计划。用户文字偏向原样展示，助手与系统内容使用 Markdown。[内容类型](https://github.com/xintaofei/codeg/blob/18046ea4ecc11a68f8f7bac9e54c99b28658dfe6/src/lib/types.ts#L111) [内容渲染](https://github.com/xintaofei/codeg/blob/18046ea4ecc11a68f8f7bac9e54c99b28658dfe6/src/components/message/content-parts-renderer.tsx#L2238)

思考使用折叠区域，计划使用独立卡片。工具卡区分执行中、完成和失败；命令显示实时输出，文件变化显示文件数及增删行，并可继续查看差异。[思考与计划](https://github.com/xintaofei/codeg/blob/18046ea4ecc11a68f8f7bac9e54c99b28658dfe6/src/components/message/content-parts-renderer.tsx#L2964) [工具展示](https://github.com/xintaofei/codeg/blob/18046ea4ecc11a68f8f7bac9e54c99b28658dfe6/src/components/message/content-parts-renderer.tsx#L2866) [文件变化](https://github.com/xintaofei/codeg/blob/18046ea4ecc11a68f8f7bac9e54c99b28658dfe6/src/components/message/reply-artifacts.tsx#L40)

审批按钮来自 Agent 返回的选项，界面不预设固定的“允许一次/永久允许”组合。Agent 提问支持单选、多选、自定义填写和提交；错误按连接、认证、额度、请求和服务分类，再提供对应恢复操作。[审批](https://github.com/xintaofei/codeg/blob/18046ea4ecc11a68f8f7bac9e54c99b28658dfe6/src/components/chat/permission-dialog.tsx#L80) [提问](https://github.com/xintaofei/codeg/blob/18046ea4ecc11a68f8f7bac9e54c99b28658dfe6/src/components/chat/ask-question-card.tsx#L436) [错误](https://github.com/xintaofei/codeg/blob/18046ea4ecc11a68f8f7bac9e54c99b28658dfe6/src/components/chat/session-failure-banner.tsx#L179)

### 3.2 Codex

Codex 的结构化会话条目包含用户消息、Agent 回复、计划、推理摘要、命令执行、文件变化、MCP 工具、网页搜索、图片、子 Agent、上下文压缩和独立工具输出。[会话条目](https://github.com/openai/codex/blob/e9633d7a0226eac91c7a791dc4f92cf8f25df2ae/codex-rs/app-server-protocol/src/protocol/v2/item.rs#L230)

Codex TUI 的主视图保持紧凑：完成后的推理在完整会话视图中保留，普通命令默认只展示少量输出行，文件修改先显示文件级摘要，失败时再展开错误。[回复与推理](https://github.com/openai/codex/blob/e9633d7a0226eac91c7a791dc4f92cf8f25df2ae/codex-rs/tui/src/history_cell/messages.rs#L1) [命令摘要](https://github.com/openai/codex/blob/e9633d7a0226eac91c7a791dc4f92cf8f25df2ae/codex-rs/tui/src/exec_cell/render.rs#L431) [文件摘要](https://github.com/openai/codex/blob/e9633d7a0226eac91c7a791dc4f92cf8f25df2ae/codex-rs/tui/src/history_cell/patches.rs#L7)

官方 App Server 将会话、回合和工作条目分别建模。会话可处于空闲、活动、系统错误等状态；活动中还能说明正在等待审批或用户输入。回合区分进行中、完成、中断和失败。[App Server](https://learn.chatgpt.com/docs/app-server#api-overview)

### 3.3 Nimbalyst 旁证

Nimbalyst 同样把消息、工具进度、交互提问、子 Agent 和回合结束投影为统一会话事件；思考默认折叠，工具和文件差异使用可展开卡片，登录、限流、上下文超限和服务错误有单独提示。[事件类型](https://github.com/nimbalyst/nimbalyst/blob/d6e1d008d9ee264a7447f3533fa9f48f158a70b0/packages/runtime/src/ai/server/transcript/types.ts#L13) [展示投影](https://github.com/nimbalyst/nimbalyst/blob/d6e1d008d9ee264a7447f3533fa9f48f158a70b0/packages/runtime/src/ai/server/transcript/TranscriptProjector.ts#L58) [错误展示](https://github.com/nimbalyst/nimbalyst/blob/d6e1d008d9ee264a7447f3533fa9f48f158a70b0/packages/runtime/src/ui/AgentTranscript/components/MessageSegment.tsx#L345)

三个项目的共同点很稳定：正文保持可读，过程信息分层收起，需要用户处理的内容始终显眼。

## 4. VibeStudio 会话内容候选

| 内容 | 默认展示 | 展开后 | 建议阶段 |
| --- | --- | --- | --- |
| 用户消息 | 完整文字、附件摘要、时间 | 附件预览 | M2 |
| Agent 回复 | Markdown 正文、Agent、时间 | 长内容保持正常阅读 | M2 |
| 思考或推理摘要 | 一行标题和状态，默认收起 | 完整可公开内容 | M2，按 Agent 能力 |
| 计划或待办 | 当前步骤和整体进度 | 全部步骤、状态 | M2，按 Agent 能力 |
| 工具调用 | 工具名称、动作、运行状态 | 输入摘要、结果和错误 | M2 |
| 命令执行 | 命令、工作目录、状态、少量输出 | 完整输出和退出结果 | M2 |
| 文件变化 | 文件名、动作、增删摘要 | 协议已提供的差异 | M2 展示；完整代码工作区后置 |
| 审批请求 | 原因、目标、Agent 提供的决策按钮 | 完整命令、差异或权限范围 | M2 |
| Agent 提问 | 问题和可选项 | 自定义输入、补充说明 | M2 |
| 错误与通知 | 分类原因和主要恢复操作 | 技术详情、原始错误 | M2 |
| 上下文与用量 | 输入区旁的简短状态 | 精确数值和来源 | M2，按 Agent 能力 |
| 子 Agent、委派、后台任务 | 一行汇总 | 子过程和结果 | 后续，除非接入时必须展示 |
| 完整终端、历史搜索、消息转任务 | 不进入首批会话正文 | 独立工具或菜单 | 后续 |

未知协议内容不能丢弃。无法识别的事件先显示为通用工具或通知卡，并保留可诊断的类型名称；不能把它冒充普通 Agent 回复。

## 5. 按钮与操作候选

下表是调研后的范围建议，仍需在 M2 模块详细设计时最终确认。

| 位置 | 操作 | 建议范围 | 规则 |
| --- | --- | --- | --- |
| Agent 回复 | 复制 | M2 | 复制可见 Markdown，不混入隐藏工具数据 |
| 长回复、思考、工具、命令 | 展开/收起 | M2 | 默认摘要稳定，展开不改变会话状态 |
| 工具和命令 | 复制结果 | M2 | 只复制用户已展开或明确选择的内容 |
| 文件变化 | 查看差异、打开文件 | 按宿主能力 | 没有项目视图时可以只展示摘要和路径 |
| 会话正文 | 滚到底部、加载更早内容 | M2 | 新消息不抢走用户正在阅读的位置 |
| 审批卡 | Agent 返回的允许、拒绝、取消等选项 | M2 | 决策随请求变化，失效后立即禁用 |
| 提问卡 | 选择、填写、提交、取消 | M2 | 回答始终发送到原请求和原会话 |
| 错误卡 | 重试、重连、登录或新会话 | M2 | 只显示当前错误真正支持的恢复方式 |
| 输入区 | 添加上下文、命令候选、发送、停止 | M2 | 能力来自当前会话；运行中输入按实测结果处理 |
| 输入区 | 模型、模式、思考等级、权限 | M2 | 仅展示 Agent 实际上报的选项 |
| 输入区 | 排队、追加到当前回合 | 后续或按能力 | 两种行为必须明确区分，不能共用一个发送动作 |
| 会话头和列表 | 重命名、分叉、置顶、归档、删除 | 后续 | 删除需要单独确认；关闭面板不结束任务 |
| 选中文字 | 引用、开新会话、保存笔记 | 后续 | 首批只保留普通选择和复制即可 |

## 6. 展示规则

- 先显示“发生了什么”，再让用户按需查看原始输入、完整输出和技术详情。
- 审批、提问、断线和失败放在消息滚动区外或提供固定待处理入口，避免被长回复推走。
- 工具状态至少包含等待、运行、完成、失败和取消；收到未知状态时显示原值并记录诊断。
- 命令输出采用固定高度摘要，展开后在卡片内滚动，不能撑开整个网格。
- 单会话保留完整上下文；网格面板保留任务、状态、最新结果和输入，非焦点面板降低过程信息密度。
- 每个操作都携带会话和请求标识。当前选中面板只影响视觉焦点，不改变消息、审批或停止的目标。

## 7. 仍需实测

- Claude Code、Codex 适配器分别会回传哪些历史内容和工具细节。
- 思考、计划、差异、终端、用量和错误是否都有稳定结构。
- 每类审批与提问实际提供哪些按钮，以及请求何时失效。
- 运行中能否追加、排队或只允许停止后再发送。
- 长历史能否分页加载，加载旧内容时是否会重复事件。

这些结果进入 M0 能力记录，并在 M2 模块设计中决定最终按钮范围。
