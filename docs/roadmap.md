# VibeStudio 开发路线图

当前进度：需求、技术、架构、前端设计及静态原型已确认；M0 详细模块设计已落档，接入验证尚未开始。

## 1. 目标与范围

依据 [需求设计](需求设计.md)、[技术设计](技术设计.md)、[架构设计](架构设计.md) 和 [前端设计](前端设计.md)，完成会话扫描、ACP 统一聊天、单会话与网格会话。

沿用界面层、本地能力层、外部工具层。项目视图、画布和其他开发工具保留入口，暂不实现业务；不增加自制桥接服务、消息数据库或后台平台。

## 3. 里程碑与分层的对应

### M0

- [外部工具层](架构设计.md#1-总体与分层)：确定目标版本和启动方式，使用现成适配器验证认证、新建、旧会话加载与真实续聊；记录四类输入区设置和用量能力的支持边界。
- [本地能力层](架构设计.md#2-两条工作路径)：用最小验证程序确认会话标识、目录与 ACP 连接能正确关联，不提前开发完整客户端。
- 界面层以已确认原型作为能力对照，不要求先实现工作台。验证结果归档到 Agent 接入和会话运行模块文档。

### M1

- [界面层](架构设计.md#1-总体与分层)：建立 Tauri、React 工程，落实公共主题与控件，完成项目栏、导航、会话列表和必要配置入口。
- [本地能力层](架构设计.md#2-两条工作路径)：复用 CCSM 的只读扫描与项目分组，提供来源、标题、目录、会话标识和异常信息，保存必要接入配置。
- 外部工具的原生历史作为扫描输入。扫描不启动 Agent，不执行任务，也不修改原始记录；本阶段不要求聊天已经可用。

### M2

- [界面层](架构设计.md#1-总体与分层)：完成单会话的历史、输入、实时回复、工具记录、提问、审批和错误展示，落实固定 Agent 图标及最新输入区布局。
- [本地能力层](架构设计.md#2-两条工作路径)：管理运行连接、会话关联、事件归属、审批与停止；草稿和阅读位置按会话保留，切换界面不销毁连接。
- [外部工具层](架构设计.md#1-总体与分层)：由现成适配器和原工具执行任务、保存原生历史。模型、思考等级、权限和上下文用量按 M0 验证结果接入，不使用演示值冒充真实能力。

### M3

- [界面层](架构设计.md#3-会话归属与并行)：复用单会话面板实现 2×2、3×3 网格、会话放入与新建、面板替换、放大和移除，以及小窗口适配。
- [本地能力层](架构设计.md#3-会话归属与并行)：验证不同会话并行、同一原生会话不重复执行，操作不随焦点改变目标，应用退出只处理自身启动的执行。
- [外部工具层](架构设计.md#1-总体与分层)：完成两类 Agent 的混合并行验证与运行依赖检查，交付 Windows 可运行包；不增加代码工作树隔离或自动合并系统。

## 4. 执行与记录

- M0 的会话运行和 Agent 接入模块已补齐验证边界、数据归属、进程生命周期和证据格式；真实接入结果仍需在验证后回填。其他模块在对应里程碑开工前继续补齐详细设计。
- 实现与验证结果持续更新到模块文档。路线图只维护里程碑状态、依赖、退出标准和整体进度，不重复存放实现细节。
- 状态统一使用未开始、进行中、阻塞、已完成。达到退出标准并有可运行功能、测试或人工确认等依据，才能标记已完成。
- 验证使用专用测试项目和可辨识会话，不把用户现有开发项目自动用作测试靶子，不删除原始会话或改写原工具认证。
- 提交前检查格式、静态分析、核心业务单测及文档双向链接；纯展示外观通过实际界面检查，不编写外观单测。
