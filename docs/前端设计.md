# VibeStudio 前端设计

确认日期：2026-09-14。

本文根据已确认的静态原型记录前端布局、控件位置和展示规则，作为后续界面实现的基准。沿用 [需求设计](需求设计.md)、[技术设计](技术设计.md) 和 [架构设计](架构设计.md)，不扩大 MVP 范围，不采用 PRD 写法。

## 1. 设计基准

界面参考 Codeg、Codex 的开发工作台：白色内容区、浅灰项目栏与侧栏、紧凑列表、细分隔线，以及清楚的选中和运行状态。界面直接进入开发工作区，不增加介绍页、大标题或装饰性区域。

MVP 聚焦会话扫描、ACP 统一聊天、单会话和网格会话。项目视图、画布及其他开发工具继续保留入口，后续补齐。保留入口不代表对应业务已经实现。

本轮确认的是三个 HTML 原型的界面展示。原型没有业务交互，任务内容、模型、权限、思考等级、上下文用量和运行状态均为演示数据。

## 2. 整体布局

窗口内铺满工作台，从上到下依次是项目栏、一级视图切换栏和当前项目的工作区。进入 Vibe Coding 后，工作区分为左侧会话栏和右侧主内容区。

```text
项目栏：项目标签、添加项目、窗口控制
一级视图：项目视图 / Vibe Coding
工作区：
  左侧：搜索、Agent 筛选、会话列表、新建会话、会话管理
  右侧：会话 / 画布、单会话 / 网格、网格布局选择
        当前会话内容或多个独立会话面板
        各会话自己的消息输入区
```

### 顶部项目栏

- 左侧显示 VibeStudio 标识，后面横向排列项目标签。
- 项目标签包含目录图标和名称，当前项目使用灰色选中底色；保留关闭和添加项目的位置。
- 项目较多时标签栏横向滚动，不挤压主工作区。
- 右侧保留最小化、最大化和关闭窗口的图标位置。

标签下方内容属于当前项目。项目重命名、完整标签管理和项目设置按需求文档后续补齐。

### 一级视图切换栏

左侧为“项目视图”和“Vibe Coding”，图标配合文字。当前视图使用深色文字和底部短线标识。右侧显示必要的运行汇总，并保留重新扫描和设置图标。

原型默认进入 Vibe Coding。“项目视图”保留为弱化、不可操作的入口，不添加版本规划说明。

### 左侧会话栏

从上到下依次为会话标题与收起图标、搜索框、Agent 来源筛选、会话列表、底部新建会话及管理入口。

- 会话按最近活动组织，原型使用今天、昨天、更早的分组。
- 每行上方为会话名称，下方为 Agent 来源与最近活动时间；右侧显示运行状态点或完成标记。
- 当前会话使用清楚的灰色选中底色，已放入网格的其他会话也有较浅的标识。
- 会话列表独立滚动，底部新建会话按钮和管理入口不随列表滚走。
- 底部保留会话数量和归档图标；归档等完整整理功能按需求文档后续补齐。

这里的 Agent 筛选用于筛选来源，不改变已有会话绑定的 Agent。

### 右侧内容工具栏

左侧是“会话”和“画布”，二者平级。右侧是单会话与网格的图标切换，以及网格布局选择和更多操作入口。

“画布”保留为弱化、不可操作的入口。当前原型只展示会话工作区，不展开画布页面或独立代码工具面板。

## 3. 单会话与网格

### 单会话

右侧显示一个会话。顶部是会话名称、工作目录、分支信息和当前状态；中间为对话记录，底部为固定消息输入区。

- 对话阅读区居中，最大宽度为 840px，避免文字在宽屏上铺得过长。
- 用户消息靠右，使用浅灰背景；Agent 回复使用白色内容面，保留图标、署名和时间。
- 思考、计划、工具、命令和文件变化按类型展示。思考、长工具输出和完整差异默认收起，审批、提问和错误保持可见。
- 工具记录使用紧凑行展示，区分等待、运行、完成、失败和取消；长路径省略显示，代码和命令使用代码字体，长内容在所属区域内滚动。
- 回复提供复制，过程卡提供展开或收起。更多消息操作按 [会话内容与操作调研](调研/会话内容与操作调研.md) 在 M2 开工前确认。
- 对话区独立滚动，输入区不随消息滚走。

### 网格会话

提供 2×2 和 3×3 两种展示布局。每个面板都代表一个独立会话，复用同一套标题、消息、状态、审批提示和输入区。

- 面板用细分隔线直接拼接，不做浮动卡片或终端墙。
- 标题栏显示 Agent 图标、会话名称、状态及放大图标；名称过长时省略显示。
- 当前聚焦面板使用细蓝色边界和很浅的标题底色。
- 每个面板独立滚动消息，保留自己的固定输入区。
- 密集布局可以把状态文字收为状态点，但保留完整状态提示；模型和思考等级不能被隐藏。
- 面板最小高度为 312px；窗口高度不足时网格区域滚动，不压扁输入框和按钮。

正式实现时，单会话与网格复用同一个会话上下文。消息、审批和停止操作只作用于目标会话；切换显示模式、移除面板或切换项目不自动结束执行。草稿和阅读位置随会话保留。

### 审批与连接错误

网格中的审批和重连区域放在消息滚动区之外、输入区上方。审批显示要执行的内容及允许、拒绝操作；连接错误显示必要原因和重新连接操作。

提示不能被长回复推走，也不能覆盖输入框。小面板可以收起辅助目录信息，确认、拒绝和重连操作必须保留。密集布局优先为这些操作让出空间。

## 4. 消息输入区

输入框下面的控件分成左右两组。三个原型使用相同顺序：

```text
左侧：添加上下文图标 → 固定 Agent 图标 → 权限选择
右侧：模型选择 → 思考等级选择 → 上下文用量饼图 → 发送 / 停止
```

### 左侧控件

- 添加上下文使用加号图标，悬停显示名称；具体内容选择操作留到实现时补齐。
- Agent 只显示图标，悬停可查看名称；不显示切换下拉框、箭头或额外名称文字。
- Agent 在创建或载入会话时确定，已有会话内不能切换到另一个 Agent。
- 权限选择紧随 Agent 图标，显示权限图标、当前权限和下拉箭头。原型以“默认权限”展示。

### 右侧控件

- 模型选择显示当前模型名称和下拉箭头，靠近发送按钮，不放在左侧 Agent 旁边。
- 思考等级紧随模型，显示当前等级和下拉箭头；完整含义通过悬停提示查看。
- 上下文用量使用 16px 的小饼图，紧靠发送按钮左侧。扇区表示当前会话已使用的上下文窗口比例，悬停显示百分比，不在输入栏增加解释文字。
- 发送使用圆形上箭头按钮，运行状态可展示为圆形停止按钮；不可执行时使用灰色禁用外观。

权限、模型和思考等级的具体选项、生效时机，以及上下文用量的数据来源，按当前 Agent 的真实接入能力在实现阶段确定。原型中的选项和百分比不能直接作为真实数据使用。

输入 `/` 时显示当前会话实际提供的命令候选，包含名称、说明和参数提示。列表随 Agent 事件更新；没有上报的命令不进入建议列表。命令候选依附输入框，不增加长期占位的说明区。

### 窄输入区

两组控件按实际可用空间换行。放不下时，右侧整组进入下一行并继续右对齐。控件顺序不变，发送按钮始终在最右侧。

不能通过隐藏模型、思考等级或上下文饼图换取空间。长模型名可以省略并保留完整提示；悬停、焦点和状态变化不应导致按钮尺寸或布局跳动。

## 5. 视觉规范

沿用原型中按 Impeccable 整理的统一主题与基础控件。正式前端使用技术设计已确定的 shadcn/ui、Tailwind CSS 和 Lucide，不新增另一套组件体系。

### 色彩

| 用途 | 当前基准 |
| --- | --- |
| 主内容与输入区 | 白色 `#ffffff` |
| 顶部项目栏 / 会话侧栏 | `#fafafa` / `#f6f6f6` |
| 悬停 / 选中底色 | `#ededed` / `#e8e8e8` |
| 区域分隔 / 控件边框 | `#e5e5e5` / `#d1d1d1` |
| 正文 / 次级文字 / 时间与提示 | `#202020` / `#575757` / `#6b6b6b` |
| 焦点与执行状态点 | 蓝色 `#3768c9` |
| 完成 / 等待审批 / 连接错误 | `#34724a` / `#875c1b` / `#b54141` |

状态色只承担明确含义。上下文饼图使用中性灰，不增加装饰色、发光效果或大面积渐变。区域层次通过底色和细边界区分，不使用浮动阴影。

### 字体与尺寸

- 界面使用 Segoe UI，中文回退到 Microsoft YaHei；代码与路径使用 Cascadia Code、Consolas 等代码字体。
- 单会话标题 16px，侧栏标题与普通正文 14px，网格正文、列表和控件标签 13px，时间和输入区选项 12px。
- 字号不随窗口宽度缩放，字间距统一为 0。
- 间距沿用 4、8、12、16、20、24、32、40px 的统一尺度。
- 项目栏高 44px，一级视图栏高 38px，主内容工具栏高 46px；普通会话行高 54px。
- 图标控件通常为 30px，网格紧凑控件为 26px；普通图标 16px，小箭头 12px。
- 常用控件圆角 6px，单会话输入容器圆角 8px，网格输入容器圆角 6px；面板之间保持直角分隔。
- 单会话文本输入区当前高 48px，网格文本输入区高 32px。

详细参数见 [主题样式](prototypes/vibestudio/styles/tokens.css)，控件和工作台规则见 [基础控件样式](prototypes/vibestudio/styles/primitives.css) 与 [工作台样式](prototypes/vibestudio/styles/workbench.css)。实现时统一复用，变更规范时同步主题和设计文档。

## 6. 不同窗口尺寸

以桌面工作台为主。当前原型的小屏规则用于缩窄窗口及展示校验，不新增独立移动端产品范围。

| 窗口宽度 | 会话侧栏 | 2×2 布局 | 3×3 布局 |
| --- | --- | --- | --- |
| 大于 1180px | 272px | 两列 | 三列 |
| 大于 860px，且不超过 1180px | 232px | 两列 | 两列 |
| 大于 640px，且不超过 860px | 232px | 一列 | 一列 |
| 不超过 640px | 56px 图标栏 | 一列 | 一列 |

小屏保留会话图标栏，展示 Agent 图标、状态点、搜索、新建和归档入口，完整会话名称通过提示查看。不能直接把会话栏隐藏掉。

单个面板宽度不超过 400px 时，消息区使用更紧凑的上下间距，并收起审批中的辅助目录行。输入控件是否换行由实际剩余宽度决定，不依赖隐藏模型名称来适配。

长标题和路径省略显示并保留完整提示；长消息换行；长代码与命令在自己的内容区滚动。项目栏、会话列表、消息区和网格各自处理滚动，避免整个页面横向溢出。

## 7. 状态与实现约束

以下状态是正式界面需要补齐的展示规则，当前原型只模拟了部分状态：

- 悬停使用浅灰底色；键盘焦点使用清楚的细蓝色轮廓。图标操作必须有名称提示和可读取的名称。
- 空会话保留输入区；无会话列表提供新建会话入口，不增加功能教程或宣传文字。
- 扫描、历史加载和连接中的提示放在对应区域，保留工作台结构，不用整页遮罩挡住其他会话。
- 运行、审批、完成、停止和失败状态按真实事件显示，不从扫描时间推测任务正在执行。
- 失败只显示必要原因和恢复操作；加载旧会话失败不能伪装为已经续接成功。
- 审批结束或失效后不保留可提交的旧审批按钮。待审批、连接中断等状态下的输入和发送能力按接入情况处理。
- 页面不展示开发备注、版本计划、“本地服务在线”等无关状态，也不为每个区域机械添加标题和说明段落。

正式实现沿用技术设计中的整体布局、会话区域、公共主题与控件划分。窗口外壳、侧栏、会话内容、输入区和网格按职责拆分；前端不直接扫描原工具文件或管理 Agent 进程，这些工作由本地能力层负责。

本次只归档设计，不开始正式客户端开发，不新增编辑器、Git 面板、画布业务或后台服务。
