# VibeStudio 架构设计

依据 [需求设计](需求设计.md) 和 [技术设计](技术设计.md)，本文记录已确认的轻量架构。MVP 聚焦会话扫描、ACP 统一聊天，以及单会话和网格会话。

完整界面与后续功能入口继续保留。本阶段不建立额外服务平台，也不提前实现项目视图、画布及其他开发工具。

## 1. 总体与分层

自建部分只有界面和 Rust 本地能力，外部编程工具直接复用。

| 层级 | 职责 |
| --- | --- |
| 界面层 | 项目栏、导航、会话列表、聊天和网格；保留完整界面规划 |
| 本地能力层 | 扫描会话、管理 ACP 连接、收发消息、处理审批与停止、保存必要配置 |
| 外部工具层 | 现成 Claude、Codex ACP 适配器及原编程工具，负责实际开发执行和原生历史保存 |

界面通过 Tauri 本地通信调用 Rust。Rust 使用现成 ACP 协议库连接适配器，不增加 HTTP 服务或独立后台平台。

编程能力、工具执行和原生历史管理由外部工具提供，不在本客户端重写另一套 Agent 引擎。

## 2. 两条工作路径

### 会话扫描

启动或刷新时，本地能力层只读扫描原工具的会话记录，整理真实项目目录与会话信息，再提供给界面展示和选择。

扫描不启动 Agent，不发送任务，也不移动、改写或删除原始会话。

### 会话聊天

用户选择已有会话或创建新会话后，本地能力层关联正确的 Agent、原生会话和工作目录，通过 ACP 加载上下文、发送任务并接收事件。

回复、工具记录、运行状态和审批都回到对应会话。加载旧会话失败时明确报告，不用空白新会话代替原上下文。

## 3. 会话归属与并行

- Rust 持有运行连接和状态，界面切换不销毁连接。
- 消息按会话统一保存显示状态，单会话和网格复用同一份数据，不重复开启上下文。
- 消息、审批和停止操作始终对应目标会话，不跟随当前项目或面板焦点改变归属。
- 同一原生会话避免重复执行，不同会话可以并行，也可以使用不同 Agent。
- 从网格移除面板只改变显示，不删除会话或自动停止执行。
- 退出时只停止本客户端启动的执行，不影响用户另外打开的 CLI。

审批请求结束或失效后，界面不能继续提交旧决定。运行状态以实际收到的事件为准，不把扫描信息推测为实时执行状态。

## 4. 数据保存

原始会话历史由原编程工具保存，本客户端只读扫描并按需加载，不建设完整消息数据库。

本地 JSON 只保存必要配置及会话关联。运行中的会话数据与面板显示分开管理，草稿和阅读位置按会话保留。

客户端完整退出后不承诺任务持续运行或进程现场自动恢复；重新打开时扫描原生历史并按可用能力续接。

## 5. 扩展与当前边界

项目视图、画布和其他开发工具的布局及入口继续保留。后续在现有界面层和本地能力层补充对应功能，MVP 不提前实现这些业务。

具体接口、适配器进程复用策略和内部文件拆分留到模块设计阶段确定，不在这里预设完整框架。

VibeX 仅参考 ACP 接入方式，不采用其完整工程作为底座。现成适配器对目标版本、认证和旧会话的兼容性仍需在实现阶段验证。

本次仅落档架构设计，不开始代码开发，不提前创建路线图或模块实现。下一步按当前讨论安排确认前端设计。
