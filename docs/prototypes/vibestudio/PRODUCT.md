# VibeStudio Prototype

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

User-requested static HTML and CSS. No application JavaScript, backend, Agent connection, or functional controls.

## Product Purpose

Show the VibeStudio desktop workspace at high fidelity before production frontend development. The core product scans existing Claude Code and Codex sessions, provides unified ACP chat, and displays parallel session grids.

## Operating Context

The confirmed project documentation is in C:/code/VibeStudio/docs. This directory is a prototype artifact, not the production application.

## Capabilities and Constraints

- Preserve the project strip, Project View/Vibe Coding navigation, session sidebar, and Conversation/Canvas positions.
- Demonstrate single-session, 2x2 grid, and 3x3 grid screens with shared visual primitives.
- Only demonstrate appearance. No send, scan, switch, approval, Agent, or window-control behavior.
- Use synthetic conversations and states. Do not read actual session content.
- Open directly as local HTML. Do not start a development server.

## Brand Commitments

The product is VibeStudio. User-pinned interface references are Codeg and Codex, with the existing confirmed workspace structure preserved.

## Evidence on Hand

- Confirmed requirement, technical, and architecture documents.
- Codeg official workspace image: https://raw.githubusercontent.com/xintaofei/codeg/main/docs/images/workspace-light.png
- Codex official public app examples inspected earlier in this task.
- No real conversation content, usage claims, or measured product performance is supplied.

## Product Principles

- Focus the prototype on scanned sessions, chat, and parallel session panels.
- Keep future navigation positions without expanding the MVP into an IDE.
- Keep source files separated by responsibility and make the delivered prototype offline-readable.
- Keep design metadata inside this prototype directory; do not modify the confirmed project documents.
