# VibeStudio 需求设计

本文按界面布局记录我们讨论的功能，保留完整工作台设想，不采用 PRD 的写法。

MVP 先做会话扫描、通过 ACP 统一聊天，以及单会话和网格会话。项目视图、代码工具、开发历史画布等功能后续补齐，原来的界面层级、入口和功能设想继续保留。

## 1. 整体布局

客户端是一个全屏开发工作台，从上到下分成三层：

- 最顶部是项目栏，用于切换当前项目。
- 项目栏下面是一级视图切换：项目视图、Vibe Coding。
- 进入 Vibe Coding 后，左侧是会话栏，右侧是主内容区。

```text
┌─────────────────────────────────────────────────────────────────┐
│ 项目 A    项目 B    项目 C    + 新建项目                         │
├─────────────────────────────────────────────────────────────────┤
│ 项目视图    Vibe Coding                                          │
├──────────────────┬──────────────────────────────────────────────┤
│ 当前项目的会话   │ 会话    画布                 单会话 / 网格  │
│                  ├──────────────────────────────────────────────┤
│ 实现登录系统     │                                              │
│ 修复支付问题     │                                              │
│ 重构数据库模块   │              主内容区域                      │
│ 增加微信登录     │                                              │
│                  │         当前会话 / 网格会话 / 历史画布       │
│                  │                                              │
│ + 新建会话       │                                              │
│ 搜索 / 会话管理  │                                              │
└──────────────────┴──────────────────────────────────────────────┘
```

这是完整界面规划。MVP 的开发重点放在会话工作区，其余区域与入口保留，后续补充对应功能。

项目负责组织开发内容；会话负责当前怎样开发；画布负责回看这个项目是怎样做出来的。

## 2. 最顶部：项目栏

项目以横向标签排列，当前项目有清楚的选中状态。项目栏下面的内容都属于当前选中的项目。

功能保留：

- 切换项目，查看对应会话和开发内容。
- 显示当前正在开发的项目。
- 新建或添加项目。
- 项目标签上的重命名、关闭和项目设置。
- 项目较多时，通过滚动或选择列表切换。

MVP 先根据扫描到的真实目录组织项目，并支持选择已有目录开始聊天。新建项目的完整操作、标签管理及项目设置后续补齐。

同一个项目可以包含 Claude Code、Codex 等不同 Agent 的会话。项目切换只改变当前查看的内容，不把后台会话的消息发送到其他项目。

## 3. 第二层：项目视图与 Vibe Coding

一级入口保持为：

```text
项目视图    Vibe Coding
```

### 项目视图：后续补齐

传统开发工作区，用于查看项目文件、代码、Git 和 Diff。

保留文件列表、代码查看与编辑、修改对照、提交历史和终端等工作区域。用户可以在这里检查 Agent 的修改、处理 Git 操作和查看运行结果。

项目视图使用当前项目或选定会话的工作目录，避免查看或修改错误位置的代码。

### Vibe Coding：MVP 优先

用于 AI Agent 开发，包含会话和开发历史画布。

会话工作区在 MVP 中实现。画布继续保留为与会话平级的模式，具体功能后续补齐。

## 4. Vibe Coding 的左侧：会话栏

每个会话代表一次独立开发上下文，例如实现登录、修复支付问题或重构数据库模块。会话之间保持独立，可以分别使用不同 Agent。

### 会话扫描：MVP

扫描本机 Claude Code 和 Codex 已有会话，按真实项目目录合并展示。

- 保留会话标题、来源、最近活动时间和原来的项目位置。
- 同一个项目中的不同来源放在一起，支持按来源筛选。
- 启动时扫描，也可以重新扫描。
- 同一会话不重复添加。
- 扫描只读，不移动、改写或删除原始会话。
- 会话记录损坏、目录缺失或读取失败时，保留其他可用会话，并显示相关原因。

扫描到的会话能够在客户端查看历史，并通过对应 Agent 继续原上下文。无法续接时明确说明，不用空白新会话代替原会话。

### 会话列表：MVP

- 切换当前会话。
- 在当前项目内新建 Claude Code 或 Codex 会话。
- 查看标题、使用的 Agent、最近活动时间及可确认的运行状态。
- 按标题搜索，默认按最近活动排列。
- 保留各会话的草稿和阅读位置。
- 会话多时列表独立滚动，长标题可以查看完整内容。

运行、等待审批、等待回复、停止或失败等状态，以实际收到的信息为准。

### 会话管理：后续补齐

左侧底部保留会话管理入口，后续增加重命名、置顶、更多排序与搜索、归档和恢复等整理功能。

会话分叉、任务交接及开发记录关联也保留为后续功能。不同 Agent 的上下文不自动互相转换，交接时需要明确交给新会话的内容。

## 5. 右侧：会话页面

主内容区默认显示当前会话，顶部提供会话与画布的模式入口。进入会话后，提供单会话和网格两种显示方式。

### 单会话与统一聊天：MVP

单会话模式占满右侧区域，适合专注处理一个任务。Claude Code 和 Codex 使用同一套聊天界面，通过 ACP 接入，保持各自独立的上下文。

顶部显示当前会话名称、Agent 和工作目录。

对话区支持：

- 查看已有历史消息。
- 输入任务，与 Agent 持续对话。
- 接收实时回复和公开工作状态。
- 查看 Agent 返回的工具调用、命令结果和错误。
- Agent 请求权限或提问时，在当前会话内回答、允许或拒绝。
- 停止当前执行，之后继续原会话。
- 长消息及工具输出按需展开。

下方保留多行输入、发送和停止操作。运行中能否追加消息按 Agent 的实际能力处理，避免重复发送。

原工具仍负责修改代码和执行命令，MVP 先把相关记录放在对话中展示，不提前建设独立代码或终端工具面板。

### 完整开发工具：后续补齐

会话页面继续保留这些功能设想：

- 查看本会话产生的代码修改和 Diff。
- 查看命令执行及完整输出。
- 查看测试、构建和运行结果。
- 打开相关文件、终端和运行预览。
- 继续当前任务，分叉或建立后续开发会话。
- 检查修改和验证结果后形成真实 Commit。

一次会话可以包含多轮开发和多个提交。Commit、修改文件及验证记录后续与对应会话和画布关联。

终端只是会话内部的一种工具，会话页面始终围绕 Agent 的开发任务组织。

## 6. 右侧：网格会话模式（MVP）

网格把右侧拆成多个会话面板，例如 2×2、3×3，可以同时运行和观察多个 Agent。

每个面板复用同一套会话页面，拥有自己的标题、Agent、状态、消息和输入区。

- 从左侧列表选择会话放入网格。
- 在空面板中创建会话，或替换面板中的会话。
- 多个面板可以分别使用 Claude Code、Codex。
- 独立发送消息、接收回复、回答审批和停止执行。
- 放大一个面板专注处理，再返回原网格。
- 从网格移除面板，不删除会话，也不自动停止执行。
- 同一个会话不重复占用多个面板，避免重复操作同一上下文。

输入及操作只作用于目标面板。其他面板继续接收自己的消息和状态，不能串线。

窗口不足时调整列数或提供滚动，保持输入区和按钮可用。更丰富的排列调整、布局保存和工作区恢复后续补齐。

网格展示的是多个 Agent 会话，不以终端网格代替会话工作区。

## 7. 与会话平级：开发历史画布（后续补齐）

画布展示整个项目的开发来路。它与会话平级，位置和入口保留，不属于 MVP 核心实现范围。

历史随着开发向上延伸，分支可以并行发展，合并后汇合。用户可以理解项目经过哪些任务、会话、Agent 和代码修改，逐步成为现在的样子。

### 节点内容

画布保留这些节点类型：

- Session：一次独立开发上下文。
- Task：一个明确的开发任务。
- Agent Run：一次 Agent 开发执行。
- Git Commit：真实代码提交。
- Branch：分支及已记录的分支操作。
- Merge：真实合并关系或已记录的合并操作。
- Test：实际测试和检查记录。

节点表达真实开发关系，包含会话、任务、执行、提交、分叉和合并。合并可能汇合多条路径，不限制为只有一个父节点的树。

### 节点详情与返回会话

- 点击 Commit，查看提交说明、修改文件、Diff 和关联会话。
- 点击 Session，回看当时已保存的完整开发上下文，并返回对应会话。
- 点击 Task 或 Agent Run，查看任务、Agent 工作记录、执行内容及结果。
- 点击 Test，查看实际执行结果和日志。
- 点击 Branch 或 Merge，查看相关提交及分支关系。

保留平移、缩放、定位、搜索、筛选和展开历史详情的操作。

### 从历史继续

可以从已有会话或选定代码节点创建后续开发会话，明确代码起点和对话来源。

查看旧会话不自动覆盖当前代码。未保存的文件、已消失的运行环境或缺失附件，只能按实际可用内容展示。

历史中的节点和关联以真实记录为依据。无法确认某个提交属于哪次会话时，不伪造关系；后续可以由用户补充确认。

## 8. 设置与通用交互

MVP 只提供接入所需设置，例如扫描位置和 ACP 程序位置，使用原工具支持的账号和配置方式。

后续保留 Agent 与模型设置、会话整理、项目设置及后台提醒、布局恢复等功能，按实际需要补齐，不作为 MVP 的前置要求。

切换项目、会话和网格不自动结束正在运行的任务。MVP 退出时只处理本客户端启动的执行；独立后台驻留和更完整的恢复后续再做。

界面风格参考 Codex 官方客户端：中性色、紧凑列表、清晰选中状态和简洁图标。所有区域保持统一控件与交互习惯。

长标题、路径和消息不会撑坏布局；空会话、扫描失败、加载和连接错误在对应区域提供必要提示及重试。文档中的 MVP 与后续标记用于划分开发范围，不作为页面上的版本说明文案。
